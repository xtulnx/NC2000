# NC1020(N) Android UI / UX Design

状态：第四版概念稿已确认，可进入 Compose 视觉实现阶段  
范围：`android` 子项目，不涉及桌面端界面

视觉稿：`nc1020-ui-concept-v4.png`。第四版按 PC1000A 真机二维键盘矩阵修正右下角键位，并保留模拟器快捷功能区。

## 设计目标

把应用从“模拟器参数工具”调整为“随手可用的文曲星”。界面保留 NC1020(N) 的银灰机身、深蓝功能区和黄绿色点阵 LCD 记忆点，但布局、反馈和设置方式遵循现代 Android 的触控习惯。

核心原则：

1. LCD 和按键始终是运行页的视觉中心，系统工具尽量退到二级层。
2. 常用操作一步可达，低频参数收纳，不在首页平铺大量文字按钮。
3. 复古来自材质、比例和色彩，不牺牲可读性与点击面积。
4. “继续运行”优先于“管理配置”，首次启动则自然切换为“导入固件”。

## 视觉方向

| Token | 建议值 | 用途 |
| --- | --- | --- |
| `AppBackground` | `#F4F0E7` | 暖白主背景，弱化普通 Material 应用感 |
| `DeviceSilver` | `#D8D7D1` | 机身与键盘面板 |
| `DeviceNavy` | `#25344B` | 功能键、主按钮、选中态 |
| `LcdBase` | `#B9C798` | 经典 LCD 背景 |
| `LcdPixel` | `#233329` | LCD 像素与文字 |
| `AccentOrange` | `#D97745` | 速度、警告、少量强调 |
| `TextPrimary` | `#202323` | 正文 |
| `TextSecondary` | `#666A67` | 状态与辅助信息 |

- 主界面使用暖白平面；不绘制手机外壳，应用边界只使用极细描边。
- 圆角克制：普通列表 10–12dp、键帽 5–7dp、底部面板顶部 20dp。
- 正文使用系统中文字体；LCD 内容继续使用原始点阵渲染，不替换为装饰字体。
- 图标统一采用单色线性图标，不再使用 emoji 作为正式入口图标。
- 真机质感集中在运行页键盘面板：首页和设置页保持现代、轻量、扁平。
- 键盘借鉴 PC1000A 的低矮深色键帽、青绿色主标、玫红/黄色副标和紧凑分组，但继续使用 NC1020 的键位映射。

## 1. 启动器：首页就是“设备”

### 信息层级

1. 标题：`文曲星模拟器`
2. 当前设备状态：`NC1020 · 已就绪`
3. 轻量横向 LCD 预览：显示真实 LCD 最近一帧；高度不超过首屏三分之一
4. 主操作：有存活会话时为 `继续使用`，无会话且固件完整时为 `启动`
5. `我的设备`：配置列表，单行呈现机型、固件版本和存档状态

### 交互

- 点击大设备卡或主按钮：启动 / 返回现有会话。
- 点击设备列表项：进入设备详情页，不在卡片中展开所有管理按钮。
- 左滑列表项：出现 `复制`、`删除`；长按拖动排序。
- 右上角 `+`：新建设备；首次启动且无设备时直接进入固件导入向导。
- 原生构建信息移入“关于”，不占据首页标题区。

### 空状态

空状态只保留一个明确任务：`添加 NC1020`，辅助文案解释需要用户自备 ROM/NOR/NAND，不展示不可执行的入口。

## 2. 运行页：沉浸式真机布局

### 竖屏结构

1. 轻量顶部栏：返回、机型、运行状态、更多。
2. 机身上半部：NC1020(N) 比例的 LCD 与银灰边框。
3. 上功能区：左侧 2×2 模拟器快捷区，右侧为青绿色应用键、玫红功能键和 F1–F4。
4. 主键区：低矮深灰键帽构成高密度 QWERTY/数字复用矩阵；副标使用弱化的玫红或黄色。
5. 底部固定模式切换：`精简 / 全键 / 游戏`。

方向键使用四枚独立小键，不采用占用空间较大的圆形方向盘。

第三、四版具体调整：

- 键盘右下角不是独立方向区，而是两行四列、尺寸完全一致的键盘矩阵：

  ```text
  [ M / 3 ] [  税  ] [ ↑ / − ] [  M−  ]
  [空格/= ] [  ←  ] [ ↓ / + ] [ →/M+ ]
  ```

- `空格/=`是单枚普通宽度键；上方向键位于上排第三列，左/下/右位于下排第二至第四列。
- 原左侧扬声器孔改为 2×2 模拟器快捷区：`加速 / 存档 / 读档 / 菜单`。
- 快捷区使用浅色现代控件样式，与下方模拟出的真机按键明确区分，避免用户误认为这些键属于 NC1020 固件。
- `加速`点按切换锁定状态，激活时使用淡青色底；长按仅在按住期间加速，松开恢复原速度。
- `存档`直接写入当前即时存档槽并显示完成反馈；`读档`在存在未保存运行数据时需要确认；`菜单`打开运行控制面板。

### 触控反馈

- 按下：按键下沉 1–2dp、亮度降低、轻触觉反馈；松开立即恢复。
- 持续按键保留当前 native key down/up 语义，滑出按键后仍确保释放。
- 同时按键以可见压下态呈现，方便组合键和游戏操作确认。
- 最小触控目标 48dp；视觉键帽可小于触控热区，但热区不能互相覆盖。
- 物理键盘输入时，对应虚拟键短暂点亮，帮助用户理解映射。

### 模式切换

- `精简`：方向、输入、退出、翻页、常用功能，适合单手操作。
- `全键`：完整 QWERTY 与功能键，允许内容纵向轻量滚动，但 LCD 保持可见。
- `游戏`：加载配置关联的控制场景；没有场景时显示创建入口，而不是空白画布。
- 切换模式不改变模拟器运行状态，也不释放无关的物理键输入。

### 横屏

- LCD 固定在左侧 44%–48% 区域，控制区在右侧。
- 游戏模式允许按键覆盖 LCD 周边，但默认不遮挡 160×80 主显示区。
- 顶部栏在静置 2 秒后收起，轻点非按键区域再次显示。

## 3. 运行控制：底部面板代替弹窗

运行中设置使用 Modal Bottom Sheet，不打断当前画面上下文。

首屏放置：

- `即时存档`
- `读档`
- `快速播放`
- LCD 显示效果：`经典 / 清晰`
- 播放速度：`1× / 2× / 4×`

次级入口：`更多设置`，包含自动存档、时间同步、保持唤醒、LCD 边框、控制场景等低频选项。

危险操作 `结束模拟器` 独立置底并使用描边橙红色。若存在未保存写入，二次确认应明确显示“最后自动保存时间”和可选的“保存并结束”。

## 关键流程

### 首次使用

`欢迎页` → `选择 NC1020(N)` → `导入所需固件` → `校验结果` → `进入设备首页`

- 固件选择按机型给出明确清单，校验成功使用勾选反馈。
- 文件名称异常但内容可识别时允许继续；真正缺失必需文件才阻断启动。
- 导入完成后默认创建一个名为 `NC1020 · 官方 3.6` 的设备配置。

### 日常启动

`首页` → `继续使用 / 启动` → `运行页`

恢复已有后台会话时不再弹配置确认；只在恢复失败时解释原因并提供重启选项。

### 保存与退出

`更多` → `运行控制` → `即时存档` → 顶部短 Snackbar `已保存 · 14:32`

结束时：无变更直接结束；有未保存数据则提供 `保存并结束 / 直接结束 / 取消`。

## 状态与反馈文案

| 状态 | 建议文案 |
| --- | --- |
| 固件完整 | `固件完整 · 可以启动` |
| 正在启动 | `正在启动 NC1020…` |
| 后台运行 | `运行中 · 点击返回` |
| 自动存档完成 | `已自动存档 · 刚刚` |
| 固件缺失 | `缺少 NAND 文件`，附 `选择文件` 操作 |
| Native 启动失败 | `无法启动此设备`，详情折叠展示，不直接抛原始错误串 |

## 无障碍与可用性验收

- 常规正文对比度不低于 4.5:1；LCD 经典模式也需要提供“清晰”高对比替代。
- 所有虚拟按键提供 content description，包含键名和当前按下状态。
- 支持系统字体放大：首页和设置自适应；键盘标签可限制到合理上限，避免破坏键位。
- TalkBack 浏览顺序与视觉顺序一致；方向键声明为一组相关控件。
- 旋转屏幕、切后台和打开底部面板时，必须释放所有仍处于 down 状态的虚拟键。

## 按键视觉形态

按键的功能、key ID、映射、按下/释放语义继续使用项目现有实现。本节只定义渲染方式。

### 精简形态

- 只显示键帽主体、现有按键文字、轮廓和材质。
- 用于空间较小的游戏场景、自定义覆盖层或用户主动选择的简化布局。

### 完整形态

- 在精简形态基础上，为键帽上方和/或下方预留辅助文字区域。
- 例如键帽主体为 `中英数`，上方印刷式辅助文字为 `SHIFT`。
- 辅助文字只作视觉说明，不新增动作，不改变按键映射，也不参与状态判断。
- 外部辅助文字不形成独立触控区域；按键点击范围仍由现有布局定义。

实现时应把视觉数据和动作数据分开。全键盘已有的 `fullKeyboardRows`、key ID 和顺序不得因视觉改造而改变；可以建立单独的、以现有 key ID 为索引的视觉说明表。

## 素材策略

- 不直接从概念图裁切带文字的完整键帽；概念图只作为视觉参考。
- 键帽圆角、底色、描边、阴影、按下位移和文字优先使用 Compose 绘制，以支持任意尺寸及状态。
- 如需要材质，只提供无文字、透明背景的纹理覆盖层；Android 交付格式优先为带 Alpha 的无损 WebP，设计母版可以保留 PNG。
- `中英数`、`SHIFT` 等文字禁止烘焙进位图素材。
- `加速 / 存档 / 读档 / 菜单`等模拟器快捷图标使用 Vector Drawable。
- 计划中的生产素材及使用约束见 `assets/README.md`。

## 本轮不实现

- 不在这轮改动 Compose 业务代码。
- 不重新设计控制场景编辑器；仅确定它从运行控制与设备详情进入。
- 不更改 native 模拟核心、固件格式或现有存档语义。

## 建议实现顺序

1. 主题 Token、图标和基础按键组件。
2. 运行页竖屏结构与按键反馈。
3. 运行控制 Bottom Sheet。
4. 启动器信息架构和设备详情页。
5. 横屏适配、空状态、错误状态与无障碍验收。
